1 · Introduction

Indigenous GCS is a native desktop ground control station for an ESP32-based flight controller. It speaks MAVLink 2 over serial or UDP, renders live telemetry, plans and uploads missions, reads and writes parameters, logs flights, and includes a built-in simulator so you can exercise every screen without an aircraft.

It is built with C++17 and Qt 6 (QML). There is no Python runtime and no browser engine — it is a single native application.

What you can do

CapabilityWhere
Live telemetry: attitude, GPS, battery, speed, headingDashboard, Flight Data
Arm / disarm with confirmationDashboard, Flight Data
Change flight modeDashboard, Flight Data
Plan, validate, upload and download missionsMission Planner
Read / write / export / import parametersParameters
Accelerometer, gyro, mag, level, RC calibrationCalibration
Fly a simulated vehicle with no hardwareSimulation
Record and export flight logsLogs
MAVLink message inspector and link statisticsDiagnostics
Build and flash ESP32 firmware from the appFirmware
NO HARDWARE? Start the simulator (Simulation page, or IGCS_AUTOSTART_SIM=1). Every screen then shows live data and you can safely explore the whole application.

2 · Install & Build — macOS

These commands install everything needed and put the finished application on your Desktop. Copy the whole block into Terminal and press Enter. Homebrew is used for Qt 6 and CMake.

BEFORE YOU START — you need the Apple Command Line Tools. If you have never built anything on this Mac, run xcode-select --install first and accept the prompt.

One-block install (recommended)

macOS · Terminal · install + build + copy to Desktop 
# ── 1. Install build tools and Qt 6 (Homebrew) ──────────────────────────
# Installs Homebrew if it is missing, then Qt 6, CMake and Ninja.
if ! command -v brew >/dev/null 2>&1; then
  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
fi
brew install qt cmake ninja git

# ── 2. Point CMake at the Homebrew Qt 6 ─────────────────
QT_PREFIX="$(brew --prefix qt)"

# ── 3. Get the source and build it ──────────────────────
cd ~/Desktop
git clone https://github.com/garvitpant/IndigenousGCS.git
cd IndigenousGCS

cmake -S . -B build -G Ninja \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_PREFIX_PATH="$QT_PREFIX"
cmake --build build

# ── 4. Run the unit tests ───────────────────────────────
ctest --test-dir build --output-on-failure

# ── 5. Put the finished app on the Desktop ──────────────────────────────
rm -rf ~/Desktop/IndigenousGCS.app
cp -R build/bin/IndigenousGCS.app ~/Desktop/

echo "Done. IndigenousGCS.app is on your Desktop."

Launch it

macOS · run 
# Normal launch
open ~/Desktop/IndigenousGCS.app

# Launch with the simulator already running (no hardware needed)
IGCS_AUTOSTART_SIM=1 ~/Desktop/IndigenousGCS.app/Contents/MacOS/IndigenousGCS

# If macOS refuses to open it because it is unsigned:
xattr -dr com.apple.quarantine ~/Desktop/IndigenousGCS.app

Build a distributable .dmg (optional)

macOS · package a DMG 
cd ~/Desktop/IndigenousGCS
QT_PATH="$(brew --prefix qt)/bin" ./tools/package-macos.sh

# Result: build/IndigenousGCS-1.0.0-macOS.dmg
# The script bundles the Qt frameworks in, so the DMG runs on a Mac
# that has never had Qt installed.
APPLE SILICON & INTEL — Homebrew installs the native build for your Mac. On Apple Silicon you get arm64; on Intel you get x86_64. To produce a build that runs on both, add -DCMAKE_OSX_ARCHITECTURES="arm64;x86_64" to the configure step.

3 · Install & Build — Windows

Open PowerShell (not Command Prompt) and paste the whole block. It installs the tools with winget, builds the app, and copies the finished folder to your Desktop.

WINDOWS 10 / 11 · 64-BIT ONLY — winget ships with Windows 11 and recent Windows 10. If winget is not recognised, install App Installer from the Microsoft Store, or install Visual Studio 2022 and Qt manually (see the manual section below).

One-block install (recommended)

Windows · PowerShell · install + build + copy to Desktop 
# ── 1. Install the toolchain ────────────────────────────
# Visual Studio 2022 Build Tools (C++), CMake, Ninja and Git.
winget install --id Microsoft.VisualStudio.2022.BuildTools --accept-package-agreements --accept-source-agreements --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
winget install --id Kitware.CMake      --accept-package-agreements --accept-source-agreements
winget install --id Ninja-build.Ninja  --accept-package-agreements --accept-source-agreements
winget install --id Git.Git            --accept-package-agreements --accept-source-agreements

# ── 2. Install Qt 6 ─────────────────────
# aqtinstall fetches Qt without needing the Qt online installer GUI.
python -m pip install --upgrade pip aqtinstall
python -m aqt install-qt windows desktop 6.8.3 win64_msvc2022_64 -O C:\Qt

# ── 3. Build the application ────────────────────────────
# Re-open PowerShell after step 1 so the new tools are on PATH.
cd $HOME\Desktop
git clone https://github.com/garvitpant/IndigenousGCS.git
cd IndigenousGCS

$QtDir = "C:\Qt\6.8.3\msvc2022_64"
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="$QtDir"
cmake --build build --config Release

# ── 4. Run the unit tests ───────────────────────────────
ctest --test-dir build -C Release --output-on-failure

# ── 5. Bundle the Qt runtime next to the .exe ───────────────────────────
& "$QtDir\bin\windeployqt.exe" --release --qmldir qml build\bin\Release\IndigenousGCS.exe

# ── 6. Copy the finished app to the Desktop ─────────────────────────────
$dest = "$HOME\Desktop\IndigenousGCS-app"
Remove-Item -Recurse -Force $dest -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Path $dest | Out-Null
Copy-Item -Recurse "build\bin\Release\*" $dest

Write-Host "Done. Launch it with: $dest\IndigenousGCS.exe"

Launch it

Windows · run 
# Normal launch
& "$HOME\Desktop\IndigenousGCS-app\IndigenousGCS.exe"

# Launch with the simulator already running (no hardware needed)
$env:IGCS_AUTOSTART_SIM = "1"
& "$HOME\Desktop\IndigenousGCS-app\IndigenousGCS.exe"

Build a Windows installer (optional)

Windows · NSIS installer 
winget install --id NSIS.NSIS --accept-package-agreements --accept-source-agreements

cd $HOME\Desktop\IndigenousGCS
.\tools\build-windows.ps1 -QtDir "C:\Qt\6.8.3\msvc2022_64"

# Result: build-windows\IndigenousGCS-1.0.0-Windows.exe
# That installer sets up Start-menu entries and an uninstaller.
POWERSHELL BLOCKS THE SCRIPT? If you see "running scripts is disabled on this system", run this once in the same window, then retry: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Manual Qt install (if winget/aqt is unavailable)

  1. Install Visual Studio 2022 with the Desktop development with C++ workload.
  2. Install CMake from cmake.org and tick "Add to PATH".
  3. Install Qt 6.5+ from qt.io, selecting the MSVC 2022 64-bit kit plus Qt Quick, Qt Quick Controls, Qt Location, Qt Positioning, Qt SerialPort and Qt SQL.
  4. Re-run the build block from step 3 above, adjusting $QtDir.

4 · First Run

On launch you get a short splash, then the Dashboard. The app never connects to anything by itself — you always choose the link.

The window is laid out in four bands:

BandWhat it shows
Top barApp name, link state, vehicle identity
Left sidebarNavigation between the 12 pages
CentreThe active page
Status barGPS, battery, link rate, mode, arm state, altitude, speed, heading, CPU, heartbeat age

Minimum useful window size is 1280×720; 1920×1080 is recommended. Everything scales with high-DPI displays.

5 · Connecting to the Flight Controller

Click CONNECT FC on the Dashboard. The Link Setup dialog opens with two tabs.

Serial (USB)

  1. Plug the ESP32 in with a USB data cable.
  2. Press the refresh ⟳ button; your port appears in the list with its description and manufacturer.
  3. Select the baud rate. ESP32 MAVLink bridges commonly use 115200.
  4. Click CONNECT.

UDP (network / Wi-Fi telemetry)

  1. Switch to the UDP tab.
  2. Set the host to 0.0.0.0 to listen on every interface.
  3. Set the port — 14550 is the MAVLink convention.
  4. Click CONNECT.
LISTENING IS NOT CONNECTED — opening a UDP socket only means the app is listening. The vehicle is reported as detected only after a valid MAVLink HEARTBEAT arrives. If the heartbeat stops for 5 seconds the link is declared lost and the UI says so rather than pretending.

Link states

StateMeaning
DISCONNECTEDNo transport open
CONNECTINGPort/socket opening
CONNECTEDHeartbeats arriving normally
DEGRADEDHeartbeats late or packets dropping
LOSTNo heartbeat for 5 s

6 · Dashboard

The at-a-glance page. It shows only real telemetry — nothing is hardcoded.

Controls on this page

ControlAction
CONNECT FCOpens Link Setup
ARMSends MAV_CMD_COMPONENT_ARM_DISARM after confirmation
DISARMSends the disarm command after confirmation
Mode selectorRequests a flight-mode change; shows an error if the FC rejects it

What is displayed

  • Attitude — roll, pitch, yaw
  • Position — latitude, longitude, altitude MSL, altitude relative
  • Speed — ground speed, air speed, climb rate
  • GPS — fix type, satellite count, HDOP
  • Battery — voltage, current, remaining %
  • System — CPU load, flight mode, arm state
  • Sensor health — per-sensor present / enabled / healthy bits
ARMING IS REAL — ARM spins propellers on a real aircraft. The confirmation dialog is not decoration. Remove props when testing on the bench.

7 · Flight Data

The instrument page. Left side is the HUD and compass; right side is a live map with a telemetry card grid beneath it.

Artificial Horizon

  • Sky and ground rotate with roll; the ladder slides with pitch
  • Heading tape across the top with cardinal marks
  • Speed tape on the left, altitude tape on the right with a climb-rate bar
  • Bottom strip: flight mode, GPS status, battery, and an armed badge that pulses red when armed

Map

  • Real OpenStreetMap tiles — no API key, no signup
  • Drag to pan, scroll wheel to zoom, pinch on a trackpad
  • + / − buttons for discrete zoom steps
  • The view follows the vehicle while it has a GPS fix

Telemetry cards

Twelve live readouts: ground speed, air speed, relative altitude, climb, GPS fix, satellites, battery %, voltage, RC RSSI, CPU, heading, altitude MSL. Values that the flight controller does not report show — rather than a misleading zero.

ARM / DISARM

Same behaviour as the Dashboard: a confirmation dialog, then a real MAVLink command, then verification against telemetry.

8 · Mission Planner

Planning a mission

  1. Click ADD WAYPOINT to arm placement mode.
  2. Set the altitude in the altitude field first.
  3. Click anywhere on the map — a numbered waypoint is placed there.
  4. Repeat. Click ADD WAYPOINT again to leave placement mode.
  5. Click VALIDATE to check the plan before uploading.

Navigating the map

GestureResult
Click and dragPan the map
Scroll wheelZoom in / out around the cursor
Two-finger pinchZoom (trackpad)
+ / −Step zoom
CENTER VEHICLEJump to the vehicle position
RELOAD MAPRe-fetch tiles if the map looks blank

On startup the map opens centred on your computer's location (resolved from your network address), falling back to New Delhi if your location cannot be determined.

Mission validation checks

  • Empty mission
  • Coordinates out of range
  • Missing or invalid home position
  • Negative or implausible altitude
  • Duplicate waypoints
  • Unsupported command types
  • Unsafe mission structure (e.g. no landing at the end)

Transfer operations

ButtonMAVLink behaviour
UPLOADMISSION_COUNT → MISSION_REQUEST_INT → MISSION_ITEM_INT → MISSION_ACK, with retries
DOWNLOADMISSION_REQUEST_LIST → item requests → local store
CLEAR FCMISSION_CLEAR_ALL and waits for acknowledgement
SIMULATOR CANNOT RECEIVE MISSIONS — the upload and clear buttons stay disabled while only the simulator is connected. The page says so explicitly instead of faking a successful transfer.

9 · Parameters

A two-panel page: parameter groups on the left, the parameter table on the right.

Reading parameters

  1. Connect a real flight controller.
  2. Click REQUEST. A progress bar fills as PARAM_VALUE messages arrive.

Finding a parameter

  • Search box — filters by name as you type
  • Group list — groups by the prefix before the first underscore, with counts

Changing a parameter

  1. Edit the value field in the row.
  2. Press Enter — the row is marked MODIFIED and the value is sent with PARAM_SET.
  3. On acknowledgement the row flashes SENT.

SEND ALL CHANGES re-sends every outstanding edit — useful if one was missed.

Export and import

EXPORT writes a tab-separated file with a header (name, value, type), one parameter per line. The importer reads the same format, so you can diff two vehicles' configurations in any text editor or spreadsheet.

10 · Calibration

Each calibration talks to the flight controller over MAVLink. Nothing is simulated.

ProcedureMethod
AccelerometerMAV_CMD_PREFLIGHT_CALIBRATION — level, then 6 orientations
GyroscopeMAV_CMD_PREFLIGHT_CALIBRATION — keep the aircraft still
MagnetometerMAV_CMD_PREFLIGHT_CALIBRATION — rotate through all axes
Level horizonStores the current attitude as level
Radio / RCReads RC_CHANNELS and shows stick travel and endpoints
ESC / outputReads SERVO_OUTPUT_RAW for output verification

Progress and result text comes from the flight controller's STATUSTEXT messages, shown live. If your firmware does not implement a procedure, the page reports "Not supported by connected firmware."

REMOVE PROPELLERS before any accelerometer, gyro, magnetometer or ESC calibration. Some calibration commands can spin motors.

11 · Simulator

The simulator generates realistic MAVLink telemetry and feeds it through the real parser, so the whole application can be exercised with no hardware.

Starting it

  • In the app: Simulation page → START
  • At launch: set IGCS_AUTOSTART_SIM=1 before starting the binary

What it simulates

  • Heartbeat, system status, GPS, attitude, position, battery, RC channels, status text
  • Flight phases: idle → takeoff → waypoint flight → hold → RTL → land
  • Drifting battery voltage and current, satellite count, and CPU load

When running, a yellow SIMULATION MODE — NO REAL AIRCRAFT banner appears at the top of the relevant pages. The simulator never touches motors or a serial port.

UPLOAD IS BLOCKED IN SIM — mission upload, parameter download and arm/disarm are disabled for a simulated vehicle, because there is no flight controller to obey them. This is deliberate.

12 · Logs

Telemetry logging is stored in SQLite so large sessions stay queryable.

  1. Click START LOGGING to open a session.
  2. Fly. Telemetry is written at 1 Hz plus every status message.
  3. Click STOP LOGGING to close the session.
  4. Pick a session in the list and click EXPORT to write it out.

Each session table shows timestamp, altitude, speed, flight mode and arm state.

14 · Firmware

Builds an Arduino sketch with arduino-cli and flashes it to the ESP32 over USB.

  1. Install arduino-cli and let the app auto-detect it, or enter the path.
  2. Click LOAD BOARDS to fetch the installed board list.
  3. Search and pick your board (for example an ESP32 Dev Module).
  4. Select the serial port and baud rate.
  5. Edit the sketch in the built-in editor.
  6. Click COMPILE & FLASH. Compile and flash logs stream live.
FLASHING IS A WRITE OPERATION — do not disconnect power or USB during flashing. Never flash a flight controller with propellers fitted.

15 · Safety Rules

The ground station is not the primary flight-safety system. Your ESP32 firmware must implement its own failsafes independently.

NON-NEGOTIABLE
  • Never arm with propellers fitted unless the aircraft is restrained and the area is clear.
  • Never rely on this application for stabilisation or emergency control.
  • Never assume GPS is valid — check the fix type and satellite count.
  • Never assume telemetry is valid — watch the heartbeat age.
  • The app never auto-arms, auto-launches, or auto-starts a mission. All of that is your explicit action.

Built-in safety behaviour

  • ARM, DISARM, RTL, LAND, mission start and firmware flashing all require confirmation.
  • Lost heartbeat is shown prominently and the vehicle is not reported as connected.
  • Battery, GPS, attitude and link warnings use four severity levels: INFO, WARNING, CRITICAL, EMERGENCY.
  • Safety-critical messages are never silently discarded.

16 · Troubleshooting

SymptomCause & fix
No serial ports listed Install the USB-serial driver for your ESP32 board (CP210x or CH340), then press ⟳. Check the cable is a data cable, not charge-only.
Port opens but no telemetry Wrong baud rate. Try 115200, then 57600. Confirm the firmware is sending HEARTBEAT.
Link shows CONNECTED but no data The status bar's HB field tells you the truth — if it climbs past 5 s the link is lost.
Map tiles are blank The app needs outbound HTTPS to tile.openstreetmap.org. A corporate proxy or firewall will block it. Click RELOAD MAP.
Values show — That field is genuinely not being reported by the flight controller. Check the MAVLink Inspector on Diagnostics.
macOS: "app is damaged" xattr -dr com.apple.quarantine ~/Desktop/IndigenousGCS.app
Windows: missing DLL on another PC Copy the whole folder, not just the .exe. The Qt DLLs must sit beside it.
Windows: app closes instantly Run it from PowerShell to see the error, and confirm windeployqt completed without warnings.
Build: Qt6 not found Pass -DCMAKE_PREFIX_PATH pointing at your Qt kit directory.
Build: Qt6Location not found Add Qt Location and Qt Positioning in the Qt Maintenance Tool.
PowerShell script blocked Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
Antivirus interferes with build Exclude the project and build directories.
